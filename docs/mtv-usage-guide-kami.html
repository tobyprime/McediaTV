01 · Overview

综合简述

MTV 是 McediaTV 在 Minecraft 中的媒体播放能力：服务端插件负责播放器实体、频道状态与权限控制，客户端模组负责实际解码、播放、心跳上报与时间轴对齐。它不是单机播放器，而是一套围绕 channel 运转的分布式播放系统。

核心结论

  • 玩家日常只需要记住一个入口：/mtv，其余操作几乎都在 GUI 内完成。
  • 服务器侧以 channel 为权威状态源，播放器只是绑定到频道的可视化承载体。
  • 公共频道与私有频道并存：私有频道服务单个播放器，公共频道可被多个播放器绑定并被搜索、管理。
  • 客户端每 5 秒发送心跳，服务端在约 30 秒无心跳时清理 audience 会话。
  • 播放进度不是持续推流同步，而是由服务端给出锚点，客户端按本地单调时间推算当前位置。

系统由哪几部分组成

层级 主要职责 对应实现
插件入口 注册命令、GUI、网络同步、心跳清理与周期广播 McediaMtvPlugin
播放器管理 创建、读取、删除播放器实体，维护实体配置与频道绑定 MtvPlayerManager
频道服务 维护播放状态、播放列表、公共频道信息、权限与持久化 MtvChannelService
GUI 交互 页面导航、点击分发、聊天输入、列表分页与页面状态保留 MtvGui 与各类 *Page
客户端会话 加载媒体、按快照同步播放位置、上报时长/完成态/挂起态 ClientChannelSession

播放器、频道与观众的关系

领域模型的关键不是“某个屏幕正在播什么”，而是“某个频道现在处于什么状态”。服务端维护 ChannelRuntimeState，其中包含媒体 URL、播放状态、播放速度、播放列表、当前游标、频道元信息与 audience 摘要。播放器实体只保存“我绑定到哪个频道”；当播放器未绑定公共频道时，会自动回落到自己的私有频道。

这意味着：同一公共频道可以被多个播放器共用；频道删除后，所有绑定它的播放器都会失去该公共频道；而私有频道会跟随播放器生命周期创建与清理。对管理员和开发者来说，先想频道，再想实体，会更接近项目真实结构。

在当前实现里，服务端不会高频推送“当前播放到第几毫秒”。它只在状态变化或周期广播时下发快照；客户端依据锚点时间、自身单调时钟与播放速度自行推算播放位置。这样能降低同步噪声，也更适合多客户端同时接入。

02 · Player Guide

玩家使用指南

对玩家而言，MTV 的使用逻辑很简单：先找到或创建播放器，再决定它是独立播放，还是绑定到某个公共频道。大部分常用功能已经集中在主菜单、播放器页、频道页与遥控器页中。

第一次使用：建议流程

  1. 输入 /mtv 打开主菜单。
  2. 如果附近已有播放器，优先点“控制最近的播放器”或“附近的播放器”。
  3. 如果没有可用播放器，点“创建播放器”，在聊天栏输入名称。
  4. 进入播放器页后，按需要配置外设、位置、激活范围与公开状态。
  5. 如果想独立播放，进入“频道设置”直接维护私有频道；如果想多人共用，去“频道列表”绑定公共频道。

主菜单能做什么

主菜单分成两块：左边偏播放器，右边偏频道。左侧包括“控制最近的播放器”“附近的播放器”“创建播放器”；右侧包括“频道控制”“频道列表”“我的频道”。这个设计刻意把“实体控制”和“频道管理”分开，避免用户把播放器和频道当成同一层概念。

如果你只是想让最近的一台屏幕播起来，最短路径通常是：/mtv → 频道控制 → 设置 URL。如果你想长期维护一套公共内容源，再去创建和管理公共频道。

播放器页面：管实体，不直接管媒体

功能 作用 适用场景
重命名 修改播放器显示名称 区分大厅屏、商店屏、活动屏
传送到位置 快速回到该播放器所在地点 地图大、设备分散时很有用
外设管理 管理屏幕与扬声器数量和配置 搭建显示墙、音响区时使用
位置与朝向 调整实体位置、偏航与俯仰 摆正屏幕、贴合建筑结构
激活范围 限制客户端在一定距离内才为该播放器工作 性能优化、避免远处无意义解码
公开 / 私有 决定谁可以编辑该播放器 多人服务器权限隔离
绑定新的频道 让该播放器改播某个公共频道 多屏同步、统一内容源

频道页面：管媒体、播放列表与时间轴

频道页面是实际“播什么、怎么播”的主战场。页面上半部是播放列表，中部是加项、清空和播放顺序，下半部是播放/暂停、前后跳时与切歌。当前实现支持把 URL 作为播放项插入到列表头、下一项或尾部，也支持直接“插入并立即播放”。

播放顺序有多种模式：顺序、随机、列表循环、当前媒体循环、播完当前停止。若你把频道当作连续节目流使用，推荐列表循环；若只是临时推送一条内容，推荐当前媒体循环或播完当前停止。

实用建议
单次播一条视频时，直接在频道页点“设置 URL”最快；做长期频道时，先把列表整理好，再切换播放顺序。把“临时插播”和“长期节目单”混在一起，后续维护会很乱。

公共频道与私有频道怎么选

私有频道适合“一台播放器只播自己的内容”；公共频道适合“多台播放器共享同一套节目流”。如果你只是装一块私人屏幕，继续使用私有频道即可；如果你想让大厅、分会场、商店橱窗统一播同一个频道，再创建公共频道并绑定多个播放器。

公共频道列表页支持搜索、只看自己的频道、创建新频道，以及把当前播放器绑定到目标公共频道。绑定后，播放器页中的“查看当前频道”会跳到公共频道详情页，统一管理频道名称、介绍、公开控制权限和删除操作。

遥控器页适合什么场景

遥控器页是轻量控制面板。它把电源、音量、频道跳转与播放控制压在一个页面里，适合站在现场做快速调试。你可以在这里调整音量、快进快退、切上一首下一首，也可以直接切到播放器设置页或频道设置页做更深入的修改。

需要注意的是，遥控器并不绕过频道权限。若当前频道未开启公开控制，只有频道创建者或拥有相应权限的玩家，才能通过遥控器更改播放内容。

03 · Server Admin Guide

服务器管理员指南

管理员需要关注的是三件事：谁能创建或编辑播放器，谁能创建或控制公共频道，以及系统在多人同时观看时如何维持同步与回收状态。

权限模型

权限节点 默认 作用
mtv.gui true 打开 MTV GUI
mtv.player.create true 创建播放器
mtv.player.edit true 编辑自己可管理的播放器设置
mtv.player.edit.others op 编辑或删除他人的私有播放器
mtv.player.teleport op 传送到播放器位置
mtv.channel.create true 创建公共频道
mtv.channel.manage.others op 管理别人创建的公共频道
mtv.channel.control.others op 控制别人创建且未公开控制的公共频道播放
mtv.admin op 打包授予上述主要管理权限

建议的服内治理策略

  • 公共大厅、商业区、活动区建议由管理员统一创建公共频道，再把播放器绑定过去。
  • 普通玩家可以保留 mtv.player.create 与 mtv.gui，但不一定要开放跨人编辑权限。
  • 如果服务器强调秩序，建议只允许少数角色拥有 mtv.channel.create，避免公共频道列表被大量低质量频道污染。
  • 对于活动运营位，通常只需要赋予频道控制权限，不需要授予频道管理或他人播放器编辑权限。

公开播放器与公开控制不是一回事

播放器“公开 / 私有”解决的是实体谁能改；公共频道的“播放权限公开 / 私有”解决的是谁能改这个频道的播放状态。两者分属不同层级，不要混用。

一个常见组合是：播放器实体由管理员维护，因此播放器仍偏私有；但它绑定的公共频道允许公开控制，于是活动主持人可以换片、暂停、跳转，而不会碰到实体位置、外设配置或删除操作。

运行与性能要点

机制 当前实现 管理员应关注什么
audience 超时 约 30 秒无心跳即清理 离线客户端不会长期占用会话
客户端心跳 约每 5 秒上报一次 用于修正状态、推进列表与统计观众数
周期广播 插件按固定 tick 周期发布同步更新 减少新加入观众或偏移客户端的停留误差
激活范围 超出距离后客户端可临时停止该播放器 用来压制远处无意义解码负载
decoder limit 挂起 客户端资源紧张时可进入挂起态 这属于运行态，不等于频道停止或播放器损坏
如果 GUI 中显示“多数观众端已挂起”，通常说明客户端端侧资源优先级或解码容量不足，而不是服务端频道丢了。此时优先检查观众位置、客户端负载与激活范围，不要第一时间删频道或重建播放器。

插件启停时会发生什么

插件启动时会加载已持久化的频道状态、恢复 audience 超时设置、建立网络服务、注册 GUI 与命令，并定期执行 audience 清理与频道同步任务。关闭时则会撤掉回调、停止定时任务、关闭网络服务、关闭仍打开的 MTV GUI，并让频道服务安全收尾。

这套流程意味着：公共频道状态是可持久化的；私有频道也会在播放器创建时初始化，并在播放器删除或注销时被清理。管理员做运维排障时，应优先区分“频道状态还在不在”和“播放器实体还在不在”，这两个问题往往来自不同层面。

04 · Developer Guide

开发人员指南

如果你要继续开发 MTV，最重要的不是先改某个 GUI 页，而是先理解当前架构把“播放控制”“实体配置”“客户端同步”拆在了哪三层。掌握这三层边界，改动才不容易串味。

入口与初始化顺序

服务端入口是 McediaMtvPlugin。它在启动时构造 MtvPlayerManager，随后取出 MtvChannelService 加载持久化状态，再挂上 MtvChannelNetworkService 的变更/删除回调，最后组装 MtvGui、命令执行器与多个事件监听器。也就是说，频道服务比 GUI 更基础，GUI 只是它的一个操作面。

服务端侧的职责切分

组件 边界 不要让它做什么
MtvPlayerManager 实体生命周期、配置读写、绑定切换 不要把播放策略硬塞进实体层
MtvChannelService 频道状态、播放列表、权限判定、持久化 不要直接渲染 GUI 或处理玩家输入
MtvPlaybackController 围绕播放器做播放操作包装 不要绕过频道层直接制造双写状态
MtvGui / *Page 导航、页面状态、交互分流 不要在页面里长期缓存业务状态
MtvChannelNetworkService 快照发布、移除广播、网络订阅 不要把领域判断逻辑塞到网络层

为什么说 channel 是核心模型

MtvChannelService 维护一个以 channelId 为键的运行态映射，并提供播放相关的全部高层操作：更新 URL、切换暂停、相对跳时、切歌、插入播放项、切换顺序、创建公共频道、删除公共频道、切换公开控制等。所有这些操作最终都汇聚到 mutatePlayback 或公共频道变更逻辑，再触发持久化与同步广播。

对后续开发来说，这个设计很关键：无论入口来自 GUI、命令、遥控器还是未来的 API，只要目标是“改变播放状态”，都应该优先复用频道服务，而不是各写一套状态推进逻辑。否则 revision、时间锚点、播放列表游标和持久化行为很容易不一致。

客户端同步机制如何工作

客户端侧以 ClientChannelPlaybackManager 按频道持有多个 ClientChannelSession。当某个界面或设备 attach 到频道时，会发送订阅请求；当快照到达时，session 会比较 revision、媒体 URL、暂停态、速度与挂起态，必要时要求强制重同步。

真正的播放过程发生在 ClientChannelSession 内部：若媒体变更就重新加载；若只是时间轴偏移，就通过估算目标位置后 seek；若暂停态或速度不一致，就同步调整播放器。客户端同时每 5 秒上报心跳，告知服务端当前媒体是否已加载、是否播放完成、时长是否可解析，以及 decoder 是否处于挂起态。 

服务端快照 → ClientChannelSession.updateSnapshot()
           → tick() 中计算目标时间轴
           → 需要时 load / seek / pause / speed 同步
           → sendHeartbeat() 回传 loaded、completed、duration、suspended

做扩展时的几个落点

  • 加新的播放策略，优先扩展 MtvChannelService 与 ChannelTimelineCalculator 一侧。
  • 加新的 GUI 操作，先决定它属于实体层还是频道层，再选择挂在 PlayerMenuPage、ChannelMenuPage 或 PublicChannelManagePage。
  • 加新的同步字段，先定义它在快照和心跳中的语义，再考虑 GUI 是否展示。
  • 若要新增持久化后端，优先围绕 ChannelRepository 抽象落地，而不是直接侵入页面或控制器。
  • 若要做脚本化控制或 Web 管理台，频道服务会是最自然的后端边界。
开发建议
在 MTV 里，最稳妥的改法通常是“先补 channel 语义，再补 GUI 操作”。如果先从界面按钮出发补逻辑，很容易让功能能点、但状态模型不完整。
05 · Appendix

附录

A. 常见问题

为什么我改了频道，另一台屏没有立刻跟上？ 先看该客户端是否仍在频道 audience 内、是否超出激活范围、是否处于 decoder 挂起态；随后再检查频道是否真的发生了 revision 变化。

为什么搜索得到公共频道，却无法控制它？ 因为搜索权限与播放控制权限是两回事。未公开控制的频道，只允许创建者或拥有 mtv.channel.control.others 的玩家控制。

为什么切回私有频道后内容变了？ 因为播放器重新回到了自身私有频道；私有频道与公共频道是两套独立状态，不共享播放列表。

B. 关键术语

player entity：世界中的 MTV 播放器实体，负责承载位置、外设与绑定信息。

channel：媒体状态的核心单元，包含播放 URL、暂停态、速度、播放列表与 audience 信息。

audience：当前订阅并参与该频道播放的客户端会话集合。

decoder suspended：客户端因资源限制而暂时挂起解码的运行态，不代表频道丢失。

C. 当前文档依据

  • 命令与权限：plugin.yml、MtvCommand
